# Dyna cross-functional review

Review date: 2026-09-06

This record keeps the material findings from the frontend, Codex app, product, and data-integrity reviews. Cosmetic preferences and speculative framework work are intentionally excluded.

| Perspective        | Material finding                                                                                                                                                                                                  | Resolution                                                                                                                                                                                                                                                                                                         |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Frontend           | Search-window items could disappear locally or receive incorrect movement controls; sequencing only considered a bounded snapshot.                                                                                | The server-filtered result is authoritative, movement flags come from the full priority group, and organization runs against that full group. Browser coverage includes filtered sequencing, source-reference search, and a match buried beyond 10,000 characters.                                                 |
| Frontend           | The dashboard needs an expanded work surface without leaving the full interactive UI embedded in the conversation; search changes were silent to assistive technology; long tokens could overflow Remote layouts. | Dyna automatically requests fullscreen after connection and renders only launch status while that request is pending. Host rejection retains an explicit retry and usable fallback because MCP Apps cannot select a Codex dock. Search results are announced and long tokens wrap.                                 |
| Product            | The main conversation could not discover item IDs, completed work remained in the active queue, failed plus waiting work appeared paused, and schedule bindings could not be retired.                             | `search-items` returns a bounded actionable brief with stable IDs. Completed work remains searchable in the pipeline but leaves the active queue/focus count. Failed or unknown task state wins over waiting. `unbind-schedule` retires a dashboard binding independently.                                         |
| Codex app          | Hosts without component UI had no useful fallback, and exact left docking or mobile task navigation cannot be guaranteed by MCP Apps.                                                                             | `list-dashboards` plus `search-items` provide the bounded text workflow. Dyna uses capability detection and host-selected presentation; exact dock placement and physical Remote behavior remain explicit host acceptance gates.                                                                                   |
| Codex app          | Publisher credentials are model-visible and become durable when copied into scheduled-task instructions; publisher/dashboard lifecycle was incomplete.                                                            | The local publisher CLI uses a fixed publisher ID and schema-valid stdin with no prompt secret. Its same-macOS-user trust boundary is explicit; local preview remains non-production-only. Lifecycle controls remain available.                                                                                    |
| Data integrity     | Stale enrichment could still overlay direct item context or crash when nullable fields were read; concurrent replacements could lose data; legacy completed tasks could lack the newly required one-line outcome. | Overlay fields apply only when their source fingerprint is current, while stale provenance remains visible. Enrichment has a compare-and-increment version. Migration backfills a precise legacy placeholder and completed work is excluded from focus counts.                                                     |
| Data integrity     | Publication validated a publisher credential before its write transaction, allowing a concurrent revoke or rotation to commit between validation and publication.                                                 | Publication now starts an immediate write transaction before credential validation. A deterministic two-connection test blocks publication behind uncommitted revoke and rotation writes and verifies that both publications fail after commit.                                                                    |
| Internal browser   | A successful background snapshot could erase a failed note, to-do, ordering, or Codex-action warning; disconnected mutations were internally rejected but still looked enabled.                                   | Operation failures now remain visible independently of connection refreshes, rejected drafts remain editable, and every server-backed mutation is visibly disabled while snapshot connectivity is unavailable.                                                                                                     |
| UX completion      | The inline brief stopped at four rows on desktop, and a wide inline-only host opened details as a full route instead of a side inspector.                                                                         | Fine-pointer desktop surfaces now show five complete 83-pixel rows while touch/mobile retains four. Every surface at least 980 pixels wide uses a non-modal 420-pixel queue plus 520-pixel inspector; narrow surfaces retain the focused route.                                                                    |
| Component stack    | The json-render compiler produced and validated a tree that was discarded, while React independently projected the snapshot through props that had already drifted from that catalog.                             | Keep Apps SDK UI for host-themed atoms, native controls for bounded filters/disclosures, and the Dyna-owned typed React catalog. Remove the redundant json-render layer; adopt it again only if a future wire makes its spec authoritative end to end.                                                             |
| UX completion      | Modal sheets allowed the dashboard to scroll behind them; Queue position was lost across views; full-record search truncated valid annotation history; local-only search had no settled live announcement.        | Centralize background locking, preserve Queue and Pipeline positions, search the complete bounded payload, and treat read-only local filtering as settled. Cross-engine tests cover modal/resize transitions, deep queues, the 200-item maximum, and buried annotations.                                           |
| UX and product     | The five-state pipeline treated “Review” as progress, hid work behind stage-selector clicks, placed desktop actions at the bottom, and used disproportionate toolbar controls.                                    | Project stored task states into four user-facing stages: To do, In Codex, Needs you, and Done. Every row carries a four-step locator; Progress shows all groups together; exact waiting/failure/unknown conditions remain visible; desktop actions sit under the inspector heading.                                |
| Source navigation  | Items exposed a generic action but no normal link, preventing right-click, copy-link, and direct provider navigation.                                                                                             | Derive safe provider URLs only from validated typed source identities and render real anchors on the row, inspector action, and provenance reference. Unsupported source types retain the opaque action instead of accepting or inventing URLs.                                                                    |
| Source recognition | Repeated provider names consumed scarce horizontal space in the compact queue and were slow to distinguish.                                                                                                       | Use closed-CSP inline SVG marks for supported providers and semantic generic sources. TWG Jira, Confluence, and Bitbucket records use their specific mark; names remain in accessibility labels, filters, schedule health, and provenance.                                                                         |
| Data integrity     | Annotation retries could duplicate notes, and unbounded dashboard/publisher creation could exceed the fixed inventory response contracts.                                                                         | Annotation requests now require a stable client UUID, reauthorize active membership inside an immediate transaction, return the original note on exact retry, and reject conflicting reuse. Dashboard and publisher creation are transactionally capped at 100 each.                                               |
| Data integrity     | Scheduled records could impersonate manual to-dos, enrichment could manufacture critical urgency, and aggregate run status did not retain which source slices failed.                                             | Scheduled publication rejects manual records at both MCP and store boundaries; critical enrichment requires source-level critical urgency. Schema v3 persists every run's normalized source slices and snapshots expose latest status plus freshness.                                                              |
| Archive lifecycle  | Completed work accumulated indefinitely, while removing irrelevant active work could falsely imply completion or discard evidence.                                                                                | Done now expires into an append-only archive after a configurable retention period. Manual dispositions remain distinct from completion; active counts exclude archived records, refreshes only flag changed history, and explicit Undo, Restore, search, history, and linked follow-ups preserve the audit trail. |
| Security migration | Pre-v3 publishers would have retained local-preview credentials, and an initial fix labeled their native schedules paused even though database migration cannot control host-owned Codex tasks.                   | Migration preserves records, bindings, and manifests but disables publishers, invalidates old tokens, and marks cached schedule state unknown. Tests prove old secrets stay denied after manifest enrollment; the native task must be reconciled and paused before re-registration.                                |
| Source health      | A revoked publisher could be reconciled back to an active cached schedule, and retained successful data or a never-run binding could make an unavailable source look live.                                        | Revoked publishers reject every status reconciliation. Retained source slices become stale, revoked and never-run bindings force delayed aggregate health, and the UI preserves historical results while labeling the revoked source explicitly.                                                                   |

## Verification

- Repository checks: formatting, lint, TypeScript, 248 tests with coverage gates, clean-build parity, skill validation, and plugin validation.
- Dyna primary UI matrix: 172 passing Chromium, WebKit, mobile Chromium, and mobile WebKit journeys.
- Dyna Firefox: 4 focused light/dark archive lifecycle journeys passed in the current run.
- Current Dyna browser run: 176 passing journeys across desktop Chromium, WebKit, Firefox, mobile Chromium, and mobile WebKit. This includes light/dark archive dispositions, automatic and immediate archive paths, Undo, later Restore, archive search, linked follow-ups, themes, cross-source prioritization and health, search, filters, reordering, to-do and annotation retry paths, opaque Codex actions, pipeline task states, expansion fallbacks, disconnect gating, scroll and modal behavior, 200-item performance, wide inline inspection, and 320-pixel layouts.
- Visual geometry: five complete rows at 1280×900, four complete rows at 390×844, a 440-pixel overlay side inspector at wide sizes, and viewport-bound controls at 320 pixels.
- Payload budget: 823,911 bytes for the complete Dyna resource, 20,889 bytes below the 825 KiB cap, including offline Oxanium and Geist Mono Latin variable fonts.
- Dependency audit: no high-or-greater vulnerabilities in 587 packages using the repository-pinned Bun 1.4 runtime; two findings are below the release threshold.
